## Architecture (the load-bearing decisions)

- **Content module in `lib/`, NOT panels/:** `src/lib/guide/guideContent.ts` — mobileFence rule 1
  bans `components/(panels|ui)` imports from `components/mobile/**`, so faqContent's location was
  un-shareable. Libs are the two-shell surface. Typed: `GuideChapter{id,title,lead,media,topics}`
  · `GuideTopic{id,title,where{desktop,mobile},body,steps,tip,media}` · `GuideMedia{src,caption,
  shell}` · `GUIDE_GOALS` (the "I want to…" router) · `GUIDE_INDEX` (flat id→node map).
- **Crosslink grammar** `[[id]]` / `[[id|label]]` in body/steps/tip — parsed by
  `lib/guide/inline.ts` (`parseGuideInline`/`guideLinkTargets`); the ONLY markup. Both renderers
  resolve label fallback from GUIDE_INDEX titles.
- **Two renderers, zero shared component code:** desktop `panels/Guide.tsx` (nav Guide toggle +
  resizable window: rail left, `.gd-scroll` inner scroll, usePanelDrag("guide")+usePanelResize,
  topic scroll+`.gd-topic--hit` flash, Esc) · /m `mobile/GuideSheet.tsx` (status-strip GUIDE chip
  → full Sheet; index view = goals + chapter rows; drill view = ‹ ALL CHAPTERS + topics; scrolls
  the `.m-sheet__body` host). CSS: `styles/guide.css` (gd-*) · `.m-g*` block appended to
  chrome.css.
- **Opener idiom:** delegated `data-open-guide` (+ optional `data-guide-target="<id>"`) document
  click listener in Guide.tsx — the data-open-upload precedent; NO new store. Welcome's HOW IT
  WORKS button uses it and calls `setExplore(false)` first (guide over a touring camera = noise).
- **FAQ ABSORBED:** Faq.tsx, faqContent.ts, faq.css, public/faq/* deleted; nav entry replaced by
  Guide; privacy(C6)/marketplace/upload copy ported into `trust`/`photo` chapters.
- **Chapters (ids):** start · move · fpv · time · target · plan · find · save · photo · mobile ·
  trust. Topic ids prefixed (`find-sunsets`, `move-pin`…) — globally unique, test-enforced.
