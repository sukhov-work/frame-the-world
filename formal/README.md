# `formal/` — machine-checked proofs (Lean 4 + Mathlib)

The Lean sources for the load-bearing math of BEST SPOT. **What belongs here, why, and the honest
limits: `.claude/claude-docs/FORMAL_VERIFICATION.md`.** This file is the mechanics.

```
formal/Ftw.lean        root module
formal/Ftw/Score.lean  the per-cell composition (bounds, monotonicity, R7, GRAZE)
formal/Ftw/Hull.lean   the architectural keystone (eye-independence of the hull)
```

## Run it

```bash
npm run proofs      # ~4 s warm: bans sorry, builds, and AUDITS THE AXIOMS
npm run proofs -- --list
```

**The build is not the gate.** A proof stubbed with `sorry` still builds — verified by mutation.
`scripts/verify-proofs.mjs` also bans `sorry`/`admit`/`native_decide` at source level and rejects
any theorem depending on an axiom outside `propext`, `Classical.choice`, `Quot.sound`.

## The layout is unusual, and deliberately so

**The Lake workspace root is the REPO ROOT, not this directory.** `lakefile.toml`,
`lean-toolchain` and `lake-manifest.json` live one level up; only `.lean` sources live here.

That is because IntelliJ's **lean4ij** plugin resolves the toolchain as
`<ideProjectRoot>/lean-toolchain` with no upward or downward walk, has no project-root or
toolchain-path setting of any kind, and then launches `lake serve -- <ideProjectRoot>` with
`cwd = <ideProjectRoot>`. With the repo root open in the IDE, the config has to be at the repo root.

Two things that look like fixes and are not:

- **A symlinked `lean-toolchain` at the root.** The plugin's existence check follows symlinks, so
  the error balloon disappears — and then Lake finds no config, falls back to plain
  `lean --server`, and every `import Mathlib.…` goes unresolved. Syntax colouring over a
  Mathlib-blind editor is strictly worse than an honest error.
- **`buildDir` / `packagesDir` pointing back into `formal/`.** Measured: Lake honours `packagesDir`
  when it computes `LEAN_PATH`, but materializes dependencies at the hardcoded
  `<workspaceDir>/.lake/packages` anyway — leaving a second, real, 601 MB git clone of Mathlib.
  One location is the only self-consistent layout.

**Consequence: `cd formal && lake build` does not work.** Lake does not search parent directories.
Build from the repo root.

## Bootstrap on a fresh machine

```bash
curl https://elan.lean-lang.org/elan-init.sh -sSf | sh   # elan is NOT on the non-login PATH
cd <repo root>
lake exe cache get     # ~5 min, 8,690 prebuilt .olean
lake build             # ~15 s
```

`~/.elan/bin` is on the *login* shell PATH via `~/.zprofile`. Scripts and non-login shells need
`export PATH="$HOME/.elan/bin:$PATH"` — `scripts/verify-proofs.mjs` does this itself.

The whole build tree — the Mathlib checkout, its prebuilt artifacts and our output — is `/.lake/`
at the repo root, **7.4 GB and gitignored**. Nothing there is hand-edited; it is regenerated by the
two commands above.

## IDE

**IntelliJ IDEA + lean4ij** (the configured path). Open the repo root as usual. After the config
files moved to the root you may need **File → Invalidate Caches… → Invalidate and Restart**, since
lean4ij runs its toolchain check at project open and a plain reload may not re-trigger it. Then open
`formal/Ftw/Hull.lean` and check:

1. no "Unable to locate lean toolchain" balloon;
2. the caret inside any `by` block renders a real goal state in the infoview, not an empty panel;
3. Cmd-click on a Mathlib identifier navigates into `.lake/packages/mathlib/Mathlib/…`, and
   `import Mathlib.…` has no unresolved-import squiggle.

If 1 passes but 2 and 3 fail, the server fell back to `lean --server`; reproduce with
`printf '' | lake serve -- "$PWD"` — anything mentioning *no configuration file* or *falling back*
is the failure.

One-time tidy: right-click `.lake` → **Mark Directory as → Excluded**, so IDEA does not index 7.4 GB.

**Alternatives, both zero-config:** VS Code / Cursor with the `leanprover.lean4` extension works
without any of the above, because it walks *up* from the opened file to find the project. And
opening `formal/`'s parent — i.e. this repo — is all lean4ij needs now.

## Working without an IDE

The CLI gives real goal states, which is enough to make progress:

```bash
export PATH="$HOME/.elan/bin:$PATH"
lake env lean Scratch.lean     # type-check one file
```

Inside that file:

- `trace_state` prints hypotheses and the goal at that point in a proof;
- an unfinished proof (`by skip`) reports `unsolved goals` **and prints the goal**;
- `exact?` searches Mathlib for a closing lemma and prints `Try this: exact …`;
- `#check @Ftw.below_chord_never_sets` prints a theorem's full statement.

## Traps

- Mathlib's dependency pin is `rev = "v4.33.1"`, **not** `version =` — the latter parses as a
  semver constraint and errors on the leading `v`.
- A multi-line `by nlinarith [...]` inside parentheses breaks Lean's bracket parse. Hoist it into a
  `have`.
- `lake-manifest.json`'s `packagesDir` must agree with the workspace layout. If it does not, Lake
  prints `manifest out of date: packages directory changed` and re-clones every dependency — and
  `session-end-ship.sh` runs `git add -A`. `/.lake/` is gitignored ahead of exactly that.
