## 0. The verdict, reconciled

The two reports AGREE on the diagnosis: the three visible defects (unstable shadows, slow off-cone
reseat, unmeasured / jetsam-killed mobile) are architectural, not tuning, and **nothing may be
optimized before it is measured** — no draw-call, triangle or GPU-ms reading exists for any pose on
any hardware, and no number has ever been taken on a real phone. The web report adds the decisive
mobile reframe: **the iPhone tile storms and Safari reloads are the WebKit jetsam kill (a memory
ceiling of ~2–3 GB per page including GPU, practical crash range far lower), not a frame-rate
ceiling** — so the mobile slice is memory-first (compressed user textures, LRU caps, UnloadTiles,
continuous render scale), and instrumentation comes before any of it.

## 2. Seams between the two reports (resolved here, or an owner call)

1. **Shadow caching vs the epoch.** The web report keys terrain shadow caching to "the terrain epoch
   PLUX already maintains"; ENGINE_STATE §12 shows that epoch bumps CITY-WIDE on every ground
   `load-model` (406 epochs in one leg). Caching keyed to it would re-render constantly under
   streaming. **Resolution:** lever 6 (per-tile invalidation) lands before lever 12.
2. **The cascade ladder.** Web: Cesium's 4 cascades sized by `maximumDistance`; ENGINE_STATE: a far
   cascade or a wide fade band on base. **Resolution:** compatible — the shadow slice measures the
   two-cascade ladder first (step 1), then decides; either way the +0.46° orbit fade stays.
3. **MSAA on TBDR.** The web report says MSAA×4 is nearly free on-tile (Rq-15) AND that HalfFloat
   MSAA×4 targets are bandwidth-heavy (Rq-11). Both are true — the resolve is on-tile, the target
   bandwidth is not. **Resolution:** keep MSAA as the mobile AA; test ×2 + a smaller target (lever
   15) against the device baseline, never SMAA on the phone.
4. **GPU heightfield seating.** Web ranks it 10 (L, "a visual smoothing layer, not a datum
   change"); ENGINE_STATE's candidates are bake-time seats + a per-feature `dy` (lever 7).
   **Resolution:** lever 7 first; GPU displacement only if the off-cone reseat time is still bad
   after it — `heightAt` stays the single vertical authority (D4, the self-confirming fixed point).
5. **Alpha-to-coverage.** Both agree it must not fail the byte-identical `high` test. **Resolution:**
   ULTRA-first (the off-state law), a pixel-diff gate, opt-in on desktop.
6. **The Hillaire sky.** L-cost with an accuracy risk to the authored curves; sky features may not
   regress (the binding rule). **Resolution:** the LAST slice, gated by exp 4's ΔE < 2 and the
   eclipse / dusk / terminator harnesses; never before the shadow and seat slices land.
7. **`__quality.force`.** ENGINE_STATE §11 names the tier-force seam `__quality.force`; the window
   seam is `window.__globeQuality` (`{ tier, dpr, leanFlat2d, mapFlat, lean }`, live getters —
   `conventions/verify.md`); the handle's `force(tier)` is `lib/globe/quality.ts:410`. Step 1 checks
   whether `force` is reachable from the window seam and exposes it if not (a DEV seam, no behaviour).
8. **Owner calls the audit does NOT make:** desktop frame rate may stay as today if mobile gets
   faster (ruled); which slice ships first after MEASURE (the plan says shadows; the owner may
   reorder after seeing the numbers); whether the still path (lever 21) and the atmosphere (19–20)
   are in scope for this revamp at all.
