## 1. Verdict on the three reported symptoms

### 1.1 "rough textures afar" — **CAUSE IDENTIFIED, high confidence**

**Primary: the draped imagery is sampled from mip level 0 with anisotropy = 1, at near-grazing incidence.**

Three independent auditors converged on this and I re-verified it directly:

- The overlay composite is built as `new CanvasTexture(canvas)` with `target.generateMipmaps = false` — `node_modules/3d-tiles-renderer/src/three/plugins/images/sources/RegionImageSource.js:112-114`; the single-tile fast path does the same at `TiledImageSource.js:37`.
- three allocates exactly one immutable level for such a texture (`node_modules/three/src/renderers/webgl/WebGLTextures.js:296-318` → `texStorage2D(..., 1, ...)` at `:1014`), and `Texture.DEFAULT_ANISOTROPY = 1` (`node_modules/three/src/textures/Texture.js:810`), so `TEXTURE_MAX_ANISOTROPY_EXT` is never issued (`WebGLTextures.js:699`).
- `src/components/globe/scene/imageryGround.ts` contains **zero** occurrences of `anisotropy|generateMipmaps|minFilter|magFilter` (verified this session). Probe validity: the same grep matches `src/components/globe/scene/baseEarth.ts:42,219`, `:259` and `src/components/globe/scene/streetNames.ts:174`.
- `maxAniso = renderer.capabilities.getMaxAnisotropy()` is computed once at `src/components/globe/StylizedTiles.ts:238` and handed to `attachBaseEarth` (`:250`) and `attachStreetNames` (`:389`) — **never** to `attachImageryGround`, whose opts contract (`imageryGround.ts:96-110`) has no such field.
- The terrain material is a bare `new THREE.MeshBasicMaterial()` with no `map` and the original disposed (`imageryGround.ts:155,161`), so the un-filtered composite is the **only** texture on the ground.
- It is sampled with implicit LOD: `tint = texture( layerMaps[ i ], layerUV.xy )` — `node_modules/3d-tiles-renderer/src/three/plugins/images/overlays/wrapOverlaysMaterial.js:121`.
- Nothing downstream compensates: `antialias:false` (`GlobeCanvas.tsx:65`), the only AA is `samples: BLOOM.msaaSamples` on the composer target (`GlobeCanvas.tsx:250-253`) — coverage AA at primitive edges, blind to texture minification inside triangles; zero `FXAA|SMAA|TAARender|SSAARender` in `src/` (verified); zero `fwidth|dFdx|textureGrad|textureLod` in `src/components/globe/**`.
- Not previously considered: `grep -rniE "mipmap|anisotrop" .claude/` → **zero** hits across the entire knowledge tree, while the same regex matches in `src/`.

**Aggravating (all real, all secondary):**
1. **No aerial perspective on the ground or buildings** — the ground grade (`imageryGround.ts:356-418`) and the building fragment injection (`buildingMaterial.ts:181-261`) contain no distance term; zero `scene.fog` in `src/` (verified; the only "fog" string is a comment at `tuning.ts:957`). The sky dome's `skyHazeBelow` aerial-perspective term (`atmosphere.ts:161-171`) is geometrically unreachable — the dome sits at `camera.far * 0.45 ≈ 81 km` (`atmosphere.ts:206`, `tuning.ts:946`) with depthTest on and **AdditiveBlending** (`atmosphere.ts:64-69`), so it can neither draw in front of 5–20 km terrain nor perform extinction even if it did. Extinction is a low-pass: its absence maximises the visibility of the aliasing above.
2. **Far-field terrain refinement rides pure distance-SSE on the primary surface.** `tiers.high.foveation: null` (verified, `tuning.ts:437`), and `peripheryErrorTarget` early-returns on null (`src/lib/globe/quality.ts:97-99`) while `applyRegions()` calls `clearRegions()` (`scene/tileFoveation.ts:67-75`) — desktop FPV runs completely un-foveated. The one lever that decouples drape texel density from mesh SSE, `GROUND.errorTarget2dDeep: 0.35` (`tuning.ts:1365`), is applied only inside the `flat2d` branch (`imageryGround.ts:566-583`), and `mapFlatNow()` early-returns `false` when `fpvActive` (`StylizedTiles.ts:4128`).
3. **T34 ground-LRU rest-trim churn** — every FPV↔2D leg evicts ground tiles, and eviction destroys the composite (`RegionImageSource.js:138-147` → `DataCache.js` release), so the far field re-blurs then re-refines. Already tracked as **T34** (`.claude/skills/frame/references/tracked-backlog.md:42`).

**Measurement that settles the primary in 30 seconds:** in `wix dev`, from an FPV eye, stamp `anisotropy = 16` + `generateMipmaps = true` on the live `layerMaps` textures and A/B one horizon frame. See §6.

### 1.2 "misaligned heights" — **CAUSE IDENTIFIED, medium-high confidence; three additive mechanisms**

**Primary: `heightAt` returns the topmost hit across every mesh still parented to the ground group — including coarse ancestors that TilesFadePlugin retains for the full 700 ms of every refine.**

- The sampler, verified verbatim this session (`src/components/globe/scene/imageryGround.ts:483-493`):
  ```
  WGS84_ELLIPSOID.getCartographicToPosition(latRad, lonRad, 12_000, _rayOrigin);
  _raycaster.set(_rayOrigin, _rayDir.negate());
  _raycaster.far = 24_000;
  const hit = _raycaster.intersectObjects(tiles.group.children, true)[0];
  ```
  A down-ray + `[0]` (three sorts ascending by distance, `node_modules/three/src/core/Raycaster.js:222`) = **the highest surface**, with no level, visibility or fade filter.
- three's Raycaster never checks `object.visible` — `Raycaster.js` `intersect()` tests only `object.layers`; `grep -c visible node_modules/three/src/core/Raycaster.js` = 0 (control: the same grep on `TilesFadePlugin.js` = 16).
- `TilesFadePlugin.setTileVisible` returns `true` while a tile fades out (`node_modules/3d-tiles-renderer/src/three/plugins/fade/TilesFadePlugin.js:449-465`), which short-circuits `invokeOnePlugin` (`TilesRendererBase.js:738-753`) so `group.remove(scene)` (`TilesRenderer.js:962-988`) never runs for the fade duration — `GROUND.fadeDurationMs: 700`, `maxFadeOutTiles: 300` (`tuning.ts:1344,1347`).
- Direction is adverse **by construction here**: the GLO-30 patch is attached as deeper children of the CWT ancestors inside the *same* renderer (`scene/terrainPatch.ts:64-75`), and the measured step is downward — city `120.4 → 85.9 m`, river `88–94 → 68.9 m` (`.claude/claude-docs/DECISIONS_ARCHIVE.md:824`). So the coarse parent wins the topmost contest for 700 ms on every refine.
- `sampleGroundM`'s `real` flag is a pure `[0, 9000]` range test (`src/lib/geo/terrain.ts:25-34`) and cannot detect a stale in-range value.
- The repo already knows the underlying fact — "Raycaster ignores `visible`" (`.claude/claude-docs/UPLIFT_PLAN.md:467`, `:168`) — and never applied it here.

**Additive #2: a building is a rigid box translated by ONE scalar at ONE centroid.** The apply loop is `for (let i = start; i < start + count; i++) pos[i*3+1] += dy` (verified, `enrichedBuildings.ts:783`), and the sample point is the run's vertex-mean centroid (`enrichedBuildings.ts:668-671` via `enrichedMask.ts:179-193`). On any slope the downhill footprint edge hangs and the uphill edge buries by ±(slope × half-diagonal). No skirt exists anywhere: `grep -rn skirt src scripts` → one hit, `terrainPatch.ts:7`, about *terrain*-tile skirts (probe proven live — the token also matches in `QuantizedMeshPlugin.js`).

**Additive #3: the FPV eye never re-samples the ground it walks over.** Verified this session: the eye is `pinP + _tempUp0 * fpvEyeM` (`StylizedTiles.ts:2471`) plus a pure world-space chord `camera.position.add(fpvWalkOffset)` (`:2630`); the 12 `fpvWalkOffset` sites are declaration (`:1245`), three zeroings (`:2253,:2305,:2469`), input-only integration (`:2585-2599`) and the apply — **nothing terrain-derived**. The street-floor guard that would catch a sunken eye is gated `!fpvActive` (`:3053`), and `controls.adjustHeight = false` on both FPV entries (`:2257,:2308`) disables the library's own radius floor. At `walkSpeedMps 22 × walkFastMult 3 = 66 m/s` (`tuning.ts:1964,1966`) kilometres of relief are seconds away; the chord also sinks `d²/2R` below the local tangent plane (2.0 m at 5 km, 7.8 m at 10 km).

**The measurement that separates them (one FPV session, no code change):** `__globe.debugSeats()` already exposes `featureAppliedMin/MaxM` and `featuresSampled/features` (`enrichedBuildings.ts:1063-1105`). Plot **applied seat delta vs horizontal distance from the bake origin**:

- a distance-flat positive bias ⇒ **F2**,
- deltas that shrink as you stare ⇒ **F4**,

**Explicitly NOT the cause of floating:** depth-buffer precision. ### Mechanisms

**#1 — Overlay filtering.** Verified this session: `imageryGround.ts` has zero filter writes; the composite is `generateMipmaps=false` (`RegionImageSource.js:112-114`) and defaults to `anisotropy=1`. Because `CanvasTexture` inherits `minFilter = LinearMipmapLinearFilter` (`Texture.js:48`) three's mipmap guard *passes* (`WebGLTextures.js:695-696`) and only the `anisotropy > 1` gate at `:699` blocks the sampler parameter — so **anisotropy alone is a legal, immediate win even with one mip level** (multiple taps at level 0). That is the low-risk half. The mip chain is the higher-risk half: each composite is an independent ClampToEdge canvas cleared transparent (`RegionImageSource.js:118`) with a `fwidth(layerUV.z)` boundary discard, so a full auto chain bleeds the transparent border inward and can produce a tile-seam grid — land a **capped 3–4-level chain** or none. Fix seam: there is no plugin option (`ImageOverlayPlugin.js:690-696` is the tile-*clipping* clone path); reach the texture via the `layerMaps` uniform (`ImageOverlayPlugin.js:1320`) or wrap the source, and cover **both** the compose path and the single-tile clone (`RegionImageSource.js:96-104`). Convention split to resolve: `baseEarth.ts:42` uses raw maxAniso, `streetNames.ts:174` caps at 8.

**#2 — `heightAt`.** Two defects in one 11-line function (verified verbatim above). (a) It passes `tiles.group.children`, which bypasses `TilesGroup.raycast` → `TilesRenderer.raycast` → `raycastTraverseFirstHit` (`node_modules/3d-tiles-renderer/src/three/renderer/tiles/TilesGroup.js:19-30`, `TilesRenderer.js:323-345`, `raycastTraverse.js:44-125`) — an acceleration structure that already ships, is `_optimizeRaycast = true` by default (`TilesRenderer.js:123`), and that **this repo already uses** at `enrichedBuildings.ts:976` (`intersectObject(tiles.group, true)`). Zero `firstHitOnly|optimizeRaycast` in `src/`. (b) `[0]` is the topmost hit and includes fading-out ancestors (see §1.2). The fix is level-aware hit selection (walk hits, prefer the deepest tile level, fall back to topmost) — **not** a `visible` filter, because `TilesFadePlugin.js:65` sets `scene.visible = inFrustum` and `heightAt` is deliberately queried outside the frustum by `horizonProfile.ts:5-18` and `planFeed.ts:283,379`. The same two-line change applies to `pickGround` (`StylizedTiles.ts:937`). Note this does **not** remove the leaf triangle walk — the per-tile height cache (the `vectorFeatures.ts:254-259` lattice pattern) or three-mesh-bvh (absent: zero hits in `src/ scripts/ package.json`) remains the order-of-magnitude lever, and is what would let the seat budgets rise 5–10×. Documented as unshipped plan item **P12** (`.claude/claude-docs/rendering/RENDERING_QUALITY_PASS.md:94`), not a T-number.

**#3 — Bake curvature.** `scripts/bake/lib/geo.mjs:55-57` states the dismissed premise ("over a few km the vertical curvature drop is sub-metre and irrelevant") — true for the original 7.4×8.9 km box, false since the widening to 20×20 km (`cities/dnipro.json:3`). `gltf.mjs:163` emits **one** root `enuToEcefMatrix(originLat, originLon, 0)` with no per-cell transform, and vertices are authored at `u = 0` in both bakers (`buildings.mjs:181,63,223`; `bake-osm2world.mjs:284-286`; trees `vegetation.mjs:296`). The runtime is open-loop: group lift = `seatRefM` (`enrichedBuildings.ts:854-855`), cell delta = `cell.seatM − seatRefM`, feature delta = `f.seatM − cell.seatM` (`:753`) — three pure translations, none of which measures the mesh's actual altitude (the one place that could, `:670-672`, discards it). `grep -rniE "curvatur|sagitta|planeRise|tangent plane"` over `scripts/bake/**`, `src/`, `.claude/conventions/`, `.claude/claude-docs/` returns zero in the seating path (probe live — it matches `horizonProfile.ts:12-13,213`). **Fix both bakers** (`bake.mjs` *and* `bake-osm2world.mjs`, which is the shipped default per `regions.ts:38`) by subtracting `(e²+n²)/(2·R_N)` at the four `projectEN` call sites. The U8 override checksum is X/Z-centroid + vertex count only (`bldgOverrides.ts:163-174`), so a Y-only re-bake **preserves stored overrides**. Secondary: `occlusion.ts` sweeps the same vertices, so the baked skyline is inflated by the same term.

**#4 — Seat sweep priority.** `enrichedBuildings.ts:889-898` picks the priority cell by squared camera distance only (re-scanned every 30 frames, `tuning.ts:1207`), gives it `ceil(16/2)=8`, then `:901-906` advances `cellList[cellSweep++ % length]` — an arbitrary order (`:625` comments "round-robin order is irrelevant"). `sampleFeatures` returns `spent==budget` for any cell with ≥8 features, so the remaining 8 land on **one** cell per frame; at 342 features/cell average that is ~43 visits per cell across ~200–389 resident cells. The `LoadAim` look-bias machinery (`loadPriority.ts:89-90`) is already **passed into this module** at `:237` and never read by the re-seat. Also: the loop never prefers never-sampled features, so after the first pass half the budget re-samples converged ones. Fix is ordering-only: top-K cells by `dist/(1+k·look·toCell)`, a never-sampled-first drain, and keep a minimum round-robin share so a 180° turn isn't a cold start.

**#5 — 45 m gate.** `acceptSample` (`enrichedBuildings.ts:694`) and the apply-time re-check (`:758-760`, `:818-821`) reject `|c − cellSeatM| > 45`. The reference is the cell **centre**, re-sampled every frame (`:863`), so as terrain refines the gate *converges on the true centre height* and the rejection becomes **structurally permanent** rather than transient. The real invalidator is not the grid bump (`dnipro.json:5` states grid 10→20 kept cells at ~1.0 km) but the U7 GLO-30 uplift: the knob was tuned when CWT served 4-vertex quads per ~2×1.6 km over Dnipro (`UPLIFT_PLAN.md:512-515`), i.e. within-cell relief was unresolvable. An auditor decoded `bakes/terrain/dnipro/13/**` and binned it into the runtime grid: **40 of 400 cells exceed 45 m (max 105.7 m at cell 18,3); 11 still exceed it under the most favourable cell-mean reference**, and those cells hold real geometry (`cell-10-7.glb` = 991 KB). Fix: gate against the cell's own sampled min/max envelope, or scale the bound by measured cell relief, and add a rejection counter to `debugSeats` (`:1063-1105`) — today the condition is invisible (`grep reject enrichedBuildings.ts` → 0).

**#6 — Seat cache.** `dispose-model` drops the CellSeat entirely (`enrichedBuildings.ts:614-628`) and `load-model` rebuilds with `seatM:null, appliedM:null` (`:551-578`, `:452-470`); trees refill with NaN (`:495-496`). The only thing re-applied is the U8 override map (`:596-608`), whose row shape (`bldgOverrides.ts:50-63`) has no terrain height. Fix: an in-memory `Map<cellUri, {cellSeat, Float32Array featureSeats, Float32Array treeSeats}>` written on dispose, consulted at load-model as a **warm start that is still re-sampled**, and **SNAP** `appliedM` on restore rather than easing at `reseatEaseK 0.12` or the cache buys convergence order but not immediacy. Key by `run.id` via `part.runIdx` (`:585`), drop on an enriched-variant switch.

The archived research warned to use the 30 m DEM "only for ground relief" (`.claude/claude-docs/archive/DNIPRO_3D_ENRICHMENT_RESEARCH_RESULTS.md:44`). **Corrected arithmetic:** because the three seat layers sum to the footprint sample by construction, a *sampled* building's absolute base equals the full DSM height at its own centroid — the error is the full local DSM-over-bare-earth excess, and the building does **not** float at its centroid (it sits exactly on what is drawn). The visible artefacts are the mound-flank edge hang, the double-counted absolute height (which also corrupts `horizonProfile`/`occlusion` and the FPV eye, since `fpvEyeAboveGroundM` rides the same sampler at `StylizedTiles.ts:3151-3153` — the walker stands on the rooftop surface), and trees, where the sampled value **is** the canopy (`:727`). Fix is bake-time DSM→DTM: rasterize the OSM footprints the enriched bake already has, plus the already-cached WBM mask, punch and inpaint, then run the existing pipeline. Runtime untouched.

**#12 — Governor never promotes in FPV.** `GlobeCanvas.tsx:490-493` parks any change with no direction test, and `applyTier` (`:333-357`) bundles the composer realloc with `setQualityTier` (`:354`) with no tile-only seam. Reachability is narrower than first claimed: a detected-`low` device has ceiling `low` and can never promote at all (`:80-81`); a detected-`high` floors at `mid` (`:103`). The full 2.5× case needs a `mid` detection (e.g. privacy-blocked GPU string) that demoted to `low` before FPV entry. **The fix is not purely monotone-safe:** `applyQualityTier` also writes `tierOverlayPx` (`StylizedTiles.ts:440`), which `stickyOverlayPx` would ratchet 256→512 and fire the fresh-instance overlay rebuild (`imageryGround.ts:501-521`) — the QA-7b storm. An `applyTileLevers` split must keep `tierOverlayPx` on the deferred path.

**#13 — Rigid box.** See §1.2 additive #2. Two orthogonal fixes: (a) sample 2–4 footprint points and store a **plane** (h0 + gradient), writing `dy` per vertex from its own x,z — but this changes the meaning of `f.seatM` and the U8 scale-about-live-base commutation proof (`enrichedBuildings.ts:768-802`) must be re-derived per vertex; (b) far cheaper and stylistically free: extrude a **base skirt** 3–5 m below `base` at bake time so residual sink/float is hidden by geometry — the classic city-tile trick, invisible from above, and it masks the residual of every other gap here. Both bakers are flat-based: the default o2w path runs OSM2World with `srtmDir` unset → ZeroInterpolator → ground Y=0 (`bake-osm2world.mjs:72,76,78`). Elongated o2w classes make (a) matter more: the shipped manifest (read this session) has **1,045 Wall, 171 RetainingWall, 60 Cliff** features, each one long run seated by a single vertex-mean centroid.

**#14 — Depth encoding.** Verified absent (§1.3). `dz ≈ z²/(near·2²⁴)`: 0.54 m @ 3 km, 5.96 m @ 10 km, 23.8 m @ 20 km, 53.6 m @ 30 km — dominated by **near**, so tightening far is worthless. Symptom is shimmer/stitching at distant contact lines, plus the `polygonOffset` differential (ground +1 vs buildings +0.5, `tuning.ts:1334,1129`) becoming a half-quantum of an increasingly coarse quantum. Fix ladder: (a) an FPV near clamp applied **after** `controls.adjustCamera` (`StylizedTiles.ts:2637`, which re-pins near to 1 m every frame via `GlobeControls.js:317-322`) — but the headroom is small: `FRUSTUM.eyeHeightM = 1.7` (`tuning.ts:1644`) and `CONTROLS.cameraRadius = 2.5` (`tuning.ts:615`) cap a safe clamp at ~1.5 m ⇒ only ~1.5×, marginal; (b) `logarithmicDepthBuffer: true` — ~1650× better at 20 km, but the 13 modules using raw `ShaderMaterial` (19 instances: `Pins.ts` + `scene/{sky,skyTarget,skyGhosts,skyTrail,dayArcs,findGhosts,stars,atmosphere,baseEarth,graticule,aimCones,tangentOverlay,placeMarkers}.ts`) each need the `logdepthbuf` chunks or they depth-test wrongly; `onBeforeCompile`-patched MeshBasic/MeshStandard (ground, buildings) inherit them free, and early-Z is already forfeited on both heavy layers by their `discard` (`imageryGround.ts:426`, `buildingMaterial.ts:225`); (c) reversed-Z + FloatType depth (`three.module.js:16077`) — **UNVERIFIED** against the `samples:4` multisampled composer path and GTAO.

**#15 — CSS-px vs device-px SSE.** `setResolutionFromRenderer` feeds CSS px (`TilesRenderer.js:420-426`; `WebGLRenderer.js:639-648` documents `getSize` as pixel-ratio-blind), used by `buildings.ts:179` and `enrichedBuildings.ts:270`, while the ground alone multiplies by dpr (`imageryGround.ts:258-262`). **Scope correction: the enriched half is inert** — the baked tileset is two-level `ADD` with root GE 512 over GE-0 leaves (`gltf.mjs:158-173`, `bake.mjs:179,188`), so errorTarget only sets the (tens-of-km) stream radius. Only the ion OSM renderer has a real hierarchy. Symptom is coarser far-field **massing**, not blur (building materials carry zero texture maps, `buildingMaterial.ts:87-91`). On `high` a straight `size*dpr` is arithmetically identical to `buildingErrorTarget 16 → 8` ⇒ ~4× tiles against a shared 400 MB LRU; ship as a tunable DPR exponent or a re-calibrated per-tier target, not a bare mirror.

**#16 — HemisphereLight.** `GlobeCanvas.tsx:238-244` constructs it **inline inside `scene.add(...)`** — no reference kept, so nothing can ever update it; repo-wide there is no writer. three sets `position = DEFAULT_UP = (0,1,0)` (`HemisphereLight.js:42`) and shades `0.5·dot(n, dir) + 0.5` (`lights_pars_begin.glsl.js:201-205`); the scene root is unrotated ECEF (`buildings.ts:207` "World space == ECEF here"; `baseEarth.ts:188` rotates the *sphere* to map +Y→ECEF +Z). At Dnipro `dot(up, +Y) = cos(48.4°)·sin(35°) = 0.381` ⇒ roofs get weight 0.690 instead of 1.0 and walls facing ECEF −Y are filled with `tokens.water` (#0C1822) purely as a function of longitude; near 90°W it inverts. **Blast radius is buildings + trees only** (the ground is unlit `MeshBasicMaterial`, `imageryGround.ts:32,155`; base earth/atmosphere are self-lit). Fix (a): keep a reference, write `hemi.position.copy(_focusUp)` in `stepKeyLightAndShadow` (`_focusUp` is already computed at `StylizedTiles.ts:2700/2703`) — needs an additive `hemiLight?` option on the orchestrator interface (`StylizedTiles.ts:214`), and it is a **real visual delta everywhere** ⇒ owner A/B. Fix (b): drive skyColor/groundColor/intensity from the same ephemeris sample the grade uses, keeping a night floor (`SUN.hemiIntensity` was raised 0.25→0.32 precisely for dark-of-moon).

**#17 — FPV shadows.** `StylizedTiles.ts:3434` gates the whole shadow pass on `!!focusHit`, where `focusHit` is the camera-forward ray → ellipsoid intersection (`:2694-2703` → `projection.ts:135-151`, `if (disc < 0) return null`). Second defect: the ortho is centred on the ray hit (`:3452-3453,3465-3466`) with half-extent `clamp(alt·0.6, 1600, 5000)` (`:3483`) — at FPV altitude it pins to the 1600 m floor while the centre sits at the hit, which for a shallow-downward look is kilometres ahead. `boundsAltK` ties reach to camera **altitude**, exactly backwards in FPV. Fix: anchor `_focus` for the shadow rig on the eye and fall back to it instead of disabling — `StylizedTiles.ts:2702` already sets `_focus`/`_focusUp` from `camera.position` when the ray misses; only the `!!focusHit` gate discards it.

**#18 — Boundary seam.** The prism clips **inside-only** (`enrichedMask.ts:97-115`, `buildings.ts:211-223` with `clipIntersection`), while both bakers keep centroid-inside straddlers **whole** (`bake.mjs:83-88`, `bake-osm2world.mjs:274-275` clamp the grid index) and Overpass returns them complete (`overpass.mjs:30-34`). Shipped-artifact proof: `bakes/enriched/dnipro-o2w/tileset.json` child regions span west 34.908742 (−460 m outside bbox) and north 48.552855 (+317 m) — enriched geometry demonstrably coexists with unclipped OSM ⇒ coincident z-fighting duplicates. Simultaneously the o2w baker **drops** centroid-outside straddlers (`bake-osm2world.mjs:271`) while the prism eats their inside half ⇒ half-building notches. The default variant suffers **both**. Plus the full altitude step from #7. Fix: one straddler rule shared by both bakers + a margin bake with an inverse-prism crossfade ring, or grow the prism by the max footprint radius.

**#19 — meta.json unread.** `grep -rn 'meta\.json' src` → two comment-only hits (`bldgOverrides.ts:20`, `wix/overrideRecords.ts:162`); probe validity from `bake.mjs:162`, `bake-osm2world.mjs:346`. The consequence is visible as a hack: the U8 pick filters street furniture with a blunt 2.5 m floor because there is "no runtime class signal (yet)" (`enrichedBuildings.ts:984-987`, `tuning.ts:1244`). **Two corrections:** the 78 %/8 m statistic is from the CLASSIC bake, which is *not* the default (`regions.ts:38` lists `dnipro-o2w` first); and the schemas are split — classic writes `{id, osm, base, height, heightSource}` with no class, o2w writes `{id, osm, cls}` with no height. **Zero `.meta.json` files exist in any bake dir** (all four predate the U8 writer), so this is re-bake-and-re-upload gated. Any height-inference change is a LOOK change on a frozen surface ⇒ **C2** owner-taste call.

**#20 — Occlusion culling.** `calculateTileViewError` has exactly one use in `src/` (the Dnipro mask, `buildings.ts:161-175`); zero `displayActiveTiles|ANY_SAMPLES_PASSED|createQuery` (control `getExtension` matches `GlobeCanvas.tsx:23`). `lib/geo/occlusion.ts`'s only consumers are `planFeed.ts:243,266`. Also note two *analytic* occlusion culls already exist for depth-free overlays (`placeMarkers.ts:134-136`, `geoLabels.ts:161-162`) — the gap is tile/geometry-level only.

**#21–#26.** Post-AA: SMAA before OutputPass is the safe spatial option (~1.5 ms, tier-gated); TAA is wrong here — the idle drift (`tuning.ts:592-598`) and FPV walk move the camera continuously and there are no motion vectors, and it would smear the Bayer dissolves. Composite aspect: `RegionImageSource.js:106-109` is unconditionally square while `setResolution` is scalar-only (`ImageOverlayPlugin.js:1636-1639`); at 48.46° the normalized range aspect is 1 : 1.51, and `calculateLevel`'s OR break means the already-fetched source carries 512–1024 px on Y but only 339–679 on X — the square canvas discards fetched Y detail *and* upsamples X. Recovery requires sizing **up** on latitude (or a constant-VRAM redistribution), not down; best as an upstream contribution. Governor: `hitches` is counted at `quality.ts:244` and has **no consumer at all**; `DeviceCaps` is read once at boot (`GlobeCanvas.tsx:72-73`); cross-browser signals that do exist are `lruCache.cachedBytes` and the U5 latency probe (`loadPriority.ts:207-215`). GlobeControls unit bug: `Ellipsoid.js:361` emits radians, `:523` expects degrees ⇒ far is 169.4 m (0.094 %) short at Dnipro — but `MIN_ELEVATION = 2550` already overshoots the true FPV horizon ~39×, so it is latent-only; **disposition is a trap line in `conventions/globe-tuning.md` next to the 0.4.28 block (`:104-111`) plus an upstream issue, not a local `camera.far` takeover** (8 modules scale impostors off `camera.far`). EXIF geoid: blast radius is the photo frustum apex and the photo-FPV eye only (`PhotoFrustum.ts:135-138`, `StylizedTiles.ts:2432`); the `Math.max(sliderAlt, terrainH + 1.7)` clamp **is** the sanctioned mitigation under binding D4 (`PROJECT_SEED.md:54`), and bundling a 1 MB grid is not justified — the correction is smaller than the vertical GPS noise D4 declares untrustworthy, and many devices write ellipsoidal height despite `GPSAltitudeRef == 0`. Document the asymmetry; do not add a runtime geoid.
